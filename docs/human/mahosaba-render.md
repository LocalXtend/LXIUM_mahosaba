# 마법소녀의 마녀재판 렌더링 최적화 설계

게임이 그리는 방식을 그대로 두지 않고, 내장 그래픽(Intel UHD 620 ~ Iris Xe)에서도 부드럽게 돌도록 LXIUM만의 렌더링 방식을 만드는 계획과 현재 구현입니다.

> 정확한 근거와 기술 목록은 AI용 문서 [`../ai/mahosaba-render.md`](../ai/mahosaba-render.md)에 있습니다. 두 문서는 항상 같이 고칩니다.

## 출발점

화면에 실제로 보이는 건 배경 한 장, 캐릭터 몇 명, 대사창뿐입니다. 무거운 건 **결과가 똑같은 화면 밖 그림을 매 프레임 다시 만드는 일**입니다. 그래서 "더 빨리 그리기"보다 "**안 그려도 되는 걸 안 그리기**"가 먼저입니다.

## 기능

**A. 설정 바로잡기 (화면 변화 없음, 구현함)**

| 기능 | 하는 일 |
|---|---|
| 2D 카메라 MSAA 끄기 | 2D 그림·UI는 가장자리가 투명이라 MSAA가 하는 일이 없습니다. 3D 법정 카메라의 MSAA는 그대로 둡니다. |
| SSAO는 법정에만 | 구석 음영 효과는 3D 법정에서만 의미가 있어서 다른 카메라에서는 끕니다. |
| 중간 텍스처 필요할 때만 | 캐릭터 합성처럼 필요 없는 곳에서 불필요한 복사를 없앱니다. |
| 프레임 제한 해제 | 60/30 대신 원하는 값으로. 기본은 모니터 주사율에 맞춤(VSync), `-1`이면 제한 없음. |

**B. LXIUM이 직접 바꾼 그리기 방식**

| 기능 | 하는 일 | 상태 |
|---|---|---|
| 바뀔 때만 다시 그리기 | 캐릭터 표정·옷·색이 그대로면 지난 사진을 그대로 씁니다. 배경의 매 프레임 복사도 같은 방식으로 건너뜁니다. 게임이 원래 쓰던 사진을 재사용하는 것이라 화면이 깨지는 일이 없습니다. (힌트의 "프레임 재투영"을 노벨 게임에 맞게 바꾼 것) | 구현 |
| 캐릭터를 화면 해상도로 | 캐릭터 사진을 1440p 기준(1500×3000)이 아니라 지금 화면에 맞는 크기로 찍습니다. 1080p면 픽셀이 56%로 줄고 화면에서는 똑같이 보입니다. 대사·UI는 영향 없음. (힌트의 "공간 해상도"를 캐릭터에만 적용) | 구현 |
| 안 보이는 법정 카메라 끄기 | 화면 분할에서 안 보이는 쪽 카메라는 그리지 않습니다. 0.2.3부터 그 화면(투명한 사각형)도 그리지 않습니다. | 구현 |
| 법정 해상도 맞춤 | 법정 카메라는 화면 크기와 상관없이 1920×1080으로 그렸습니다. 화면(창) 크기에 맞춰 그립니다. 1080p 이상이면 원래와 같습니다. | 구현 (0.1.1) |
| 법정 반 프레임 | 법정 카메라가 멈춰 있으면 두 프레임에 한 번만 그리고, 사이에는 지난 그림을 그대로 보여 줍니다. 카메라가 움직일 때는 매 프레임 그려서 화면 이동이 끊기지 않습니다. (힌트의 "프레임 재투영"을 법정에 맞게) | 선택 (4차: -2.0 ms, 프레임 간격이 고르지 않아 기본은 끔. 0.5.2에서 숨어 있던 법정 화면이 다시 나타날 때 오래된 장면이 한 프레임 보일 수 있던 문제를 고침) |
| 법정 MSAA 끄기 | 법정 그림의 MSAA 2배를 끕니다. 가장자리는 FXAA가 다듬습니다. | 기본 (0.2.1, -1.1 ms, 화면 같음) |
| 법정 후처리 끄기 | 법정 카메라의 후처리를 끕니다. 효과 값이 모두 0이라 실제로 하는 일은 FXAA뿐인데, 메인 카메라가 화면 전체에 FXAA를 한 번 더 합니다. | 기본 (0.2.1, -0.7 ms) |
| 깊이 프라이밍 | SSAO가 이미 계산한 깊이로 벽·바닥 조명 계산을 픽셀당 한 번만 합니다. | 뺌 (4차: 효과 없음) |
| SSAO 가볍게 | 법정 SSAO를 절반 해상도·낮은 품질로 계산합니다. | 기본 (0.2.1, -1.2 ms, 화면 같음) |
| 법정 건물 캐시 | 법정 카메라가 멈춰 있는 동안 바닥·벽·계단의 조명 결과를 한 번만 그려 두고 다시 읽었습니다. | 지움 (0.5.0. 화면은 같았지만 0.11 ms밖에 줄지 않음) |
| 법정 바뀔 때만 그리기 | 법정 카메라가 보는 것이 그대로인 프레임은 법정을 다시 그리지 않고 지난 그림을 그대로 보여 줍니다. 카메라 위치, 캐릭터의 그림·위치·투명도, 법정의 물체·조명 중 하나라도 바뀌면 그 프레임에 바로 다시 그립니다. 불이 켜져 있는 동안은 매 프레임 그리고, 1초마다 한 번은 무조건 다시 그립니다. "반 프레임"과 달리 멈춰 있는 동안 프레임 간격이 고릅니다 | 기본 (0.5.1, `[Stage] CourtChangeOnly`. 12차: -2.14 ms, 151 → 224 fps, 화면 같음) |
| 빠른 변화 감지 | "바뀔 때만 다시 그리기"가 변화를 확인하는 방식을 바꿨습니다. 최근에 바뀐 캐릭터와 연출(전환 효과)이 도는 동안은 매 프레임, 나머지 캐릭터는 4프레임에 한 번씩 돌아가며 확인합니다. 확인 비용이 약 4분의 1로 줄고, 놓친 변화는 최대 3프레임 늦습니다 | 기본 (0.4.0, `FastDetect`. 10차: 모드 CPU 32% 감소, 11차: 47% 감소) |
| 복사 없이 바로 그리기 | 전환 효과 복사 단계 자체를 없애고 화면에 바로 그립니다. | 후보 |
| 카메라 없이 합성 | 캐릭터 전용 카메라 대신 Naninovel의 가벼운 합성 방식을 씁니다. | 후보 |

**C. LXIUM 전용 셰이더**

Unity 에디터 없이 만듭니다. 게임에 들어 있는 원본 셰이더를 틀로 써서 이름표(속성 이름, 값이 들어갈 자리)만 남기고, 실제 계산 코드는 Windows 기본 셰이더 컴파일러로 직접 컴파일한 LXIUM 코드로 바꿔 끼웁니다. 게임과 같은 형식이라 버전이 안 맞을 걱정이 없고, 원본 코드는 들어 있지 않습니다. 결과물(셰이더 3개, 약 30 KB)은 모드 DLL 안에 들어 있어 따로 설치할 파일이 없습니다.

| 셰이더 | 하는 일 | 상태 |
|---|---|---|
| FireLite | 법정 불을 가볍게. 원본은 픽셀마다 텍스처를 8번 읽는데, 그중 2번은 늘 같은 값이고 1번은 간단한 곡선이라 식으로 바꿔 4번으로 줄였습니다. 불꽃이 없는 빈 영역(마스크의 54%)은 중간에 계산을 끝냅니다. 불 재질의 셰이더만 바꿔 끼워서, 게임이 불을 켜고 끄는 연출과 색·속도 값은 그대로 따릅니다 | 기본 (0.2.1. 불 비용 0.93 → 0.21 ms) |
| ActorDirect | 전환 효과 + 색 + 선명화를 한 번에 화면에 그림 | 후보 |
| Sharpen | 줄인 그림을 키울 때 선명하게 (FSR의 RCAS 방식) | 후보 |
| CourtLite | 법정 바닥·계단·벽·단상을 가볍게. 원본(URP Lit)은 이 게임 빌드에 그림자·SSAO가 켜진 변형만 남아 있어서, 그림자도 SSAO도 없는 지금도 픽셀마다 그림자 맵·SSAO를 읽고 반사 큐브맵 3장을 섞습니다. 같은 조명식(스포트라이트 2개, GGX)은 그대로 두고 이것들만 빼서 바닥은 텍스처 읽기 9 → 5회, 명령어 약 300 → 137개, 벽·단상은 2회로 줄였습니다 | 기본 (0.3.2, `CourtLite`. 165 → 185 fps, 바닥·벽·계단·단상 모두 원본과 같음) |

FireLite는 원본의 "깊이 페이드"(불 판이 벽·바닥과 닿는 곳을 흐리게 하는 효과)를 뺐습니다. 그 경계가 조금 또렷해질 수 있습니다. Direct3D 11(게임 기본)에서만 동작하고, 다른 그래픽 API에서는 원본 불을 씁니다.

대화 장면은 A와 "바뀔 때만 다시 그리기"만으로 UHD 620급에서도 120fps를 노려볼 만합니다. 재판 장면은 법정 3D가 남아 있어서 법정 쪽 기능과 셰이더가 더 필요합니다. (모두 측정 전 추정)

**하지 않는 것**

- 병렬 처리(Async): 노벨 진행과 Unity 기능은 한 스레드에서만 안전합니다. 그래픽 작업은 이미 엔진이 나눠 돌리고 있습니다.
- 투명 → 불투명(Opaque Ice): 위 기능 뒤에는 투명 그림이 몇 장 안 남아 효과가 작습니다.
- 화면 전체 해상도 낮추기: 대사·UI가 같은 카메라라 글자가 흐려집니다. 대신 캐릭터만 줄입니다.

## 멈춤(로딩 랙) 줄이기 (0.6.0)

게임을 직접 실행해 Windows 이벤트 추적으로 긴 프레임을 하나씩 뜯어봤습니다. 고친 것은 결과가 원래와 같고, 순서나 방법만 바꿨습니다.

| 원인 | 고친 방법 | 상태 |
|---|---|---|
| 처음 보는 글자를 폰트에 넣을 때마다 폰트의 합자·커닝 표 전체를 다시 읽음 (불러오기 화면 0.43초 멈춤의 79%) | 새로 넣는 글자는 그 표를 읽지 않게 함. 한글 음절에는 합자가 없어 모양은 같음 | 기본 (`[Text] FastGlyphs`) |
| Naninovel이 리소스가 있는지 확인할 때마다 수만 개 목록을 처음부터 훑음 (재판 시작 0.3·0.5초 멈춤) | 경로 색인을 만들어 바로 찾음. 원래 함수와 결과를 690번 비교해 다른 것 0 | 기본 |
| 모드 코드를 처음 실행할 때 그 자리에서 컴파일 (0.05~0.07초) | 게임 시작 때 미리 컴파일 | 기본 |
| 화면 패널이 꺼져 있어도 매 프레임 IMGUI가 돎 | 패널을 켤 때만 돌게 함. 패널을 처음 켤 때의 멈춤은 남음 | 일부 |
| 새 글자를 그리는 시간 (대사 한 줄에 새 글자가 많으면 0.1~0.18초) | 남는 프레임에 미리 그려 두기 | 후보 |
| 되감기용 상태 저장의 문자열 만들기 (0.12초) | 그대로면 다시 쓰기 | 후보 |
| 캐릭터를 처음 그릴 때 8K 그림 올리기 | 업로드 설정 조정 실험 | 후보 |

같은 세이브로 타이틀 → 불러오기 → 재판 → 심문 개시를 지나며 잰 결과:

| | 평균 fps | 하위 1% 프레임 | 가장 긴 프레임 | 0.1초 넘는 멈춤 | 0.25초 넘는 멈춤 |
|---|---|---|---|---|---|
| 0.5.2 | 154.5 | 21.2 ms | 0.50초 | 12번 | 4번 |
| 0.6.0 | 177.5 | 16.4 ms | 0.23초 | 6번 | 0번 |

## 모드 자체 비용 줄이기 (0.6.1)

캐릭터가 바뀌었는지 확인하는 방법을 바꿨습니다. 예전에는 4프레임마다 캐릭터 조각 그림 수백 장의 상태를 돌아가며 확인했는데, 이제는 Naninovel이 표정·옷을 바꿀 때 보내는 신호를 받아서 그때만 확인합니다. 신호를 놓친 경우를 대비해 캐릭터마다 2초에 한 번은 직접 확인합니다.

- 확인 비용: 프레임당 0.22~0.34 ms → 0.035 ms
- 같은 그림을 안전하게 다시 그리는 일: 초당 11번(1번에 1.5~2 ms, 잠깐 끊기는 원인) → 초당 약 1번
- 불러오기·재판·심문을 지나는 동안 신호로 못 잡고 직접 확인에서야 발견된 변화: 0번

## 설치해서 써 보기 (런처 전)

1. BepInEx 6 **IL2CPP** 빌드(be.785 이상, Windows x64)를 게임 폴더(`manosaba.exe` 있는 곳)에 풀고 게임을 한 번 실행했다 끕니다 (첫 실행은 오래 걸립니다)
2. `LXIUM_mahosaba.dll`을 `BepInEx/plugins/LXIUM_mahosaba/`에 넣습니다
3. 설정은 `BepInEx/config/LXIUM_mahosaba.cfg` (첫 실행 때 생깁니다)

## 어떻게 확인하나 (렌더 실험실)

1. 설정 파일에서 `RenderLab = true`
2. 캐릭터가 나오는 대화 장면이나 재판 장면에서 **F10**
3. 약 50초 동안 화면을 그대로 둡니다 (측정 중에는 프레임 제한을 풉니다). 0.5.0에서는 이렇게 잽니다
   - 게임 원래 상태 → 지금 설정(기준)
   - 진단: 법정 카메라를 잠깐 멈춤 → 남은 시간이 대사·UI·캐릭터 몫
   - 법정 바뀔 때만 그리기 켜기 / 끄기
   - 모든 단계에 모드 자신이 쓴 CPU 시간(`modCpu`)도 함께 적습니다
   - 마지막에 기준을 한 번 더 (노트북 발열로 느려진 만큼 보정)
   - PgDn 플래그 패널을 켜 두면 단계마다 바뀌는 플래그가 초록·빨강으로 보입니다 (스크린샷에는 안 찍힘)
4. 결과는 `BepInEx/LXIUM_mahosaba/<시각>/` 폴더의 `lab.txt`와 스크린샷. 스크린샷이 서로 똑같아 보이면 "화면 변화 없음"이 맞는 것입니다

## 설정

| 항목 | 기본값 | 설명 |
|---|---|---|
| `TargetFps` | 0 | 0 = 모니터 주사율(VSync), -1 = 제한 없음, 숫자 = 그 fps |
| `MsaaOff` | 켬 | 화면 변화 없음 |
| `Ssao` | Off (0.2.2) | 768p·1080p 측정 모두 끄거나 가볍게·원래 품질이어도 법정 화면이 화소까지 같았음. 1080p에서 원래 품질은 5.1 ms |
| `IntermediateAuto` | 켬 | 화면 변화 없음 |
| `ChangeOnly` | 켬 | 화면 변화 없음 |
| `Character Resolution` | 0 (화면 맞춤) | 1이면 원래 크기. 캐릭터를 크게 확대하는 연출이 신경 쓰이면 1 |
| `Stage Resolution` | 0 (화면 맞춤) | 1080p보다 작은 화면에서는 세밀한 무늬가 아주 살짝 덜 또렷함. 1이면 원래(1920×1080 고정). 0.5처럼 직접 정하면 더 가벼워지고 부드러워짐 |
| `HiddenSkip` | 켬 | 화면 변화 없음 |
| `[Stage] MsaaOff` | 켬 (0.2.1) | 측정 장면에서 화면 차이 없음 |
| `[Stage] PostOff` | 켬 (0.2.1) | 거의 차이 없음 (FXAA 두 번 → 한 번). 게임 옵션에서 후처리를 끄면 법정 쪽 FXAA는 켜 둠 |

| `[Stage] HalfRate` | 끔 | 켜면 카메라가 멈춰 있을 때 불·캐릭터 변화가 반 박자 늦음. 법정 바뀔 때만 그리기가 켜져 있으면 멈춘 장면은 이미 건너뛰므로 불이 타는 장면에서만 차이가 남 |

| `[Stage] FireLite` | 켬 (0.2.1) | 불 판이 벽·바닥과 닿는 경계가 또렷해질 수 있음. 실제 불 연출에서 자세히 보면 원본과 조금 다름 (사용자 확인, 신경 쓰이면 끄면 됨) |

기본값은 4·5차 측정 결과로 정했습니다. 이전 버전을 쓰던 설정 파일에는 옛 기본값이 적혀 있어 그대로 남으니, 업데이트했다면 위 값으로 바꿔 주세요.

게임 옵션의 "포스트 프로세싱"을 끄면 빠지는 건 FXAA뿐입니다 (다른 효과는 원래 0). 1080p에서 약 1 ms 가벼워지고 글자가 조금 더 선명해집니다. 이때 LXIUM은 법정 쪽 FXAA를 다시 켜서 법정 가장자리는 그대로 다듬습니다.

## 화면 패널 (PgUp·PgDn)

화면 오른쪽에 나옵니다. 측정 스크린샷에는 찍히지 않습니다.

- **PgUp: 프레임 통계** (최근 1초)
  - FPS, 하위 1%(가장 느린 1% 프레임 기준), 상위 1%(가장 빠른 1%)
  - 프레임 시간(평균 ms)
  - 바뀐 시간: 플래그가 바뀌면 바뀌기 직전 1초 평균과 비교한 차이. 실험실(F10)을 돌리면 단계마다 얼마나 달라지는지 바로 보입니다
  - 모드 CPU: LXIUM이 프레임마다 쓰는 CPU 시간 (패널을 켜면 패널 그리는 비용도 포함)
- **PgDn: 플래그 목록**
  - 지금 실제로 켜진 기능은 초록, 꺼진 기능은 빨강
  - 마우스를 이름 위에 올리면 왼쪽에 설명(무엇을 하는지, 측정값, 더 개선할 여지)이 나옵니다
  - 실험실(F10)이 도는 동안에는 단계마다 바뀌는 플래그가 그대로 보입니다
