# 대사·UI 최적화 연구

2026-10-18부터 기존 렌더링 작업과 별도로 대사와 UI의 반복 작업을 조사했습니다. 게임 원본 파일을 바꾸지 않고 모드로만 동작하며, 화면 품질과 게임 진행을 유지하는 것이 조건입니다. Windows 10·11을 대상으로 하지만 Windows 10 별도 실기 시험은 아직 하지 않았습니다.

600 fps는 여전히 목표입니다. CPU 작업을 조금 줄인 것을 600 fps 달성으로 부르지 않습니다. 그래픽 칩이 메인 화면 한 장을 그리는 데 3 ms 이상 걸리면 그 부분도 따로 줄여야 합니다.

## 대사가 다 나타난 뒤에는 글자 갱신 쉬기

원래 게임은 대사가 다 나타난 뒤에도 모든 글자의 투명도를 다시 계산하고, 그래픽 칩에 색상 데이터를 올립니다. 새 실험 `[Text] RevealReuse`는 모든 글자의 표시가 완전히 끝났을 때만 이 반복을 쉬게 합니다.

새 대사, 되감기, 글자 재배치, 화면을 다시 켜는 동작이 오면 원래 계산을 다시 합니다. 글자가 서서히 나타나는 속도나 글꼴·해상도·색을 바꾸는 방식은 아닙니다. 특별한 투명도 효과가 있는 대사는 원래 방법을 사용합니다. 검증 상태와 기본값은 아래 결과에서 확인할 수 있습니다.

## 시도했지만 넣지 않은 것

- **보이지 않는 UI 그림자 검사 생략:** 타이틀 시험에서는 생략할 작업이 없었고, 새 검사 때문에 오히려 느려졌습니다. 실험 코드는 제거했습니다.
- **후처리 효과 목록 캐시:** 엔진이 이미 효과가 없을 때 빠져나가는 처리를 하고 있어 추가하지 않았습니다.
- **숨은 UI 갱신을 통째로 정지:** 기존 포커스·입력 처리를 해칠 수 있어 넣지 않았습니다.
- **UI 클릭 검사 줄이기:** 앞으로 조사할 후보입니다. 안 보이는 UI도 의도적으로 뒤쪽 클릭을 막을 수 있어, 투명하다는 이유만으로 검사를 없애면 안 됩니다.

## 확인 방법

개발용 진단 로그는 실제로 글자 갱신을 몇 번 생략했는지 기록합니다. 같은 대사를 그대로 둔 채 켬·끔을 번갈아 측정하고, 대사 화면도 비교합니다. 세이브를 불러오는 중이거나 대사가 없는 화면은 개선 효과를 판단하는 자료로 쓰지 않습니다.

실험실(F10)의 끝부분에 대사 갱신 켬·끔 비교를 추가했습니다. 끝나면 원래 설정으로 돌아옵니다. 더 자세한 함수 근거, 재현 명령, 실패한 실험, AI 인계 사항은 [AI용 문서](../ai/mahosaba-ui.md)에 함께 남깁니다.

## 결과와 남은 검증

0.7.0 개발본에 실험 기능으로 넣었으며 **기본은 끔**입니다. `[Text] RevealReuse=true`로 시험할 수 있습니다. 공식 배포 버전은 아직 0.5.2입니다.

1080p 재판의 완성된 40글자 대사를 유지한 시험에서 해당 글자 갱신 CPU가 프레임당 약 **0.050 → 0.018~0.019 ms**로 줄었습니다. 켬·끔을 번갈아 잰 전체 프레임은 평균 **5.24 → 5.18 ms**로, 변화가 약 1% 수준입니다. 이 결과로 전체 게임의 FPS 향상이나 600 fps 달성을 주장하지 않습니다.

네 번 캡처한 세 줄 대사 영역은 화소까지 같았습니다. 불러오기, 완성된 대사 유지, 다음 문장으로 넘어가서 다시 표시되는 동작을 확인했습니다. 되감기·같은 문장 재배치·특수 글자 효과·다른 모드 조합과 Windows 10 실기 시험은 남아 있어 기본을 켜지 않았습니다.

다음 AI가 실패한 후보를 다시 기능으로 오해하지 않도록 코드 위치, 설정, 함수 주소 공유 검사, 재현 명령, 유효·무효 측정을 AI용 문서에 나눠 기록했습니다.
